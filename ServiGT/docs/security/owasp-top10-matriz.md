# Matriz OWASP Top 10 — ServiGT

Matriz de riesgos de seguridad de ServiGT mapeada a OWASP Top 10:2025 y OWASP API Security Top 10:2023, basada en evidencia real de código (controladores, modelos, middleware, rutas, configuración y Docker Compose).

- **Fecha:** 2026-08-28
- **Metodología:** análisis en el código y revisión de cada cambio, antes de incluirlo en la matriz. No se ejecutó `composer audit` / `npm audit`  por que no hay lockfile de Composer en el repositorio (ver A03) tampoco se corrieron comandos que alteraran estado.

## Cómo leer la matriz

Cada fila indica un **tipo**:
- **Vulnerabilidad confirmada**: evidencia de código muestra el hueco de forma directa, sin necesitar interpretación de reglas de negocio.
- **Decisión de producto**: el comportamiento existe a propósito y es correcto para el modelo de marketplace de contacto directo, pero no está realmente explícito en el código (como en un Resource dedicado), por lo que se recomienda hacerlo explícito en vez de dejarlo como comportamiento implícito de un modelo sin `$hidden`.
- **Riesgo residual aceptado**: el hueco existe, tiene impacto bajo/medio, y se documenta con fecha de revisión en vez de bloquearlo.

## 3. Resumen

**Cubierto:** las 10 categorías de OWASP Top 10:2025 y las 8 categorías priorizadas de API Security Top 10:2023 (API1, API2, API3, API4, API5, API6, API8, API9) fueron auditadas con evidencia de código real. API7 (SSRF) y API10 (Unsafe Consumption) se marcaron explícitamente como no aplicables porque el backend no realiza requests HTTP salientes.

**Categorías sin hallazgos** (controles ya correctos o superficie inexistente): A05 Injection, API5 BFLA, A10 Mishandling of Exceptional Conditions (ya mitigado y probado por `SecureErrorAndHealthTest.php`), y el invariante de créditos/cotizaciones de A08 (transacciones, locks e idempotencia ya implementados correctamente).

**Riesgos residuales pendientes de revisión** (con la fecha de esta matriz, 2026-08-28, como punto de partida — se sugiere revisar en 90 días o antes de cualquier salida a producción real, lo que ocurra primero, es decir **antes del 2026-11-26**):
- Secretos de `docker-compose.yml` reutilizados en un server público (condicionado a confirmar si `servigtdev.com` corre este mismo compose).
- Tokens Sanctum sin expiración + almacenamiento en `localStorage`.
- Falta de logging/alerting de eventos de seguridad (A09).
- Falta de inventario consolidado de la API (API9).
- Exposición de `email`/`telefono` de proveedores en rutas públicas sin un Resource que la declare explícitamente.

**Vulnerabilidades confirmadas de mayor severidad, sin follow-up ticketado todavía** (recomendado priorizar antes que las demás): las tres filas de BOLA/mass assignment sobre `ProviderController` (`uploadDocumento`, `getDocumentos`, `store`) y la exposición combinada de documentos de identidad vía storage público.

Ningún hallazgo de esta matriz fue corregido en código; este documento es puramente un registro de auditoría, sin cambios de código asociados.
